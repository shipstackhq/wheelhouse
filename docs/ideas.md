# Ideas

A place to write down ideas before they are work. Separate from docs (which describe decided things) and from issues (which are committed
work). Not designed in detail yet.

## Why

Ideas come up constantly (in meetings, in chat, in agent sessions) and get lost. Putting them in the backlog clutters it; putting them in docs
buries them. Ideas need their own light, low-commitment home.

## What an idea is

- Title and free text.
- Author (a person or an agent).
- Status: `new`, `exploring`, `promoted`, `parked`.
- Comments and reactions, so the team can weigh in.
- Workspace-wide, optionally tagged to a team.

## Key action: promote

An idea becomes an issue or a project with one action. The new item links back to the idea, and the idea is marked `promoted`, so the trail
from "someone thought of this" to shipped work is kept.

## Agents

Agents can file ideas too (through MCP): anything worth considering that came up during a chat or a run, without creating an issue.

## Risks

- **Graveyard.** Ideas pile up and nobody looks. Statuses and an occasional review (for example, at cycle planning) keep it alive.
- **Overlap with issues.** Keep ideas deliberately thin: no priority, estimate, assignee or cycle. Those arrive on promotion.

## Scope for a first version

List and detail pages, create, comment, status, promote to issue. Nothing else.
